1 How to evaluate a video

  1. Open Videos and click Evaluate. The annotation timer starts and only counts while the page is visible.
  2. Play the video. Press Mark Start when you see an indicator, and Mark End when it finishes (End is optional for instant events).
  3. Choose the problem: type to filter the list, or pick Create new problem to register it with its severity and type.
  4. Choose the indicator and the task moment, add comments if needed, and click Save Annotation.
  5. Check your work in the 1. Annotation table, 2. Problem table and Problem summary tabs. Use to fix a mistake.
  6. When done, click Finish Evaluation. This records the finish time in 3. Time annotation.

Press ? anywhere in the panel to open this guide without leaving the video.

2 Indicators indicator_code

Based on actions performed on the UI
ACT Wrong action
An action does not belong in the correct sequence; is omitted; is replaced by another action; or actions are performed in reversed order.
DISC Discontinues action
User points at a function as if to start executing it, but then does not; or stops executing an action before it is finished.
EXE Execution problem
Execution of the action is not done correctly or optimally.
REP Repeated action
An action is repeated with the same effect.
CORR Corrective action
An action is corrected with a subsequent action (or sequence of actions), or an action is undone.
STOP Task stopped
Starts a new task before having successfully finished the current task.
Based on verbal or non-verbal behaviour of the worker
GOAL Wrong goal
User formulates a goal that cannot be achieved with the product or does not contribute to the task goal.
PUZZ Puzzled
User indicates not knowing how to perform the task or which function is needed, or not being sure whether an action is needed.
RAND Random actions
User indicates that the current action(s) are chosen randomly.
SEARCH Searches for function
User cannot locate a specific function, or searches for a function the analyst knows does not exist.
DIFF Execution difficulty
User has physical problems executing an action, or finds it difficult or uncomfortable.
DSF Doubt, surprise, frustration
User is not sure an action was executed properly, does not understand its effect, is surprised by it, or finds the effect unsatisfactory or frustrating.
REC Recognition of error
User recognises a preceding error, or understands something previously not understood.
QUIT Quits task
User recognises the current task was not finished successfully, but continues with the next one.

Source: Vermeeren et al. (2002). DEVAN: A tool for detailed video analysis of user test data. Behaviour & IT, 21(6).

3 Task moments task_moment

Qualification optional
Tests or qualifications taken by workers, before or after the initial instructions. E.g. language proficiency test, browser check.
Instructions
Any instructions shown to the worker, usually at the beginning, sometimes also during the task.
Demographic questionnaire optional
Questions about the worker's demographic details. May contain validity-check questions.
Training
Interactive or non-interactive demos or tests that help understand the instructions. E.g. quiz, interactive demo, video.
Main task
The main activity: the actual data collection that will be used later.
Final questionnaire optional
Questions about the experience with the main task. E.g. motivation questionnaire.
Payment
Payment information.
Help/Support/Feedback
Any help, support or feedback channel offered to workers.

4 How to write a problem problem

A usability problem is "an aspect of the system and/or a demand on the user which makes it unpleasant, inefficient, onerous or impossible for the user to achieve their goals in typical usage situations." (Lavery et al., 1997)

From the system / task perspective

The [Task/UI element] [problem] resulting in the [worker's difficulty]

  • The initial instructions contain too much text, resulting in the worker skimming parts of it.
  • Some images are too dense, resulting in workers annotating just parts of a tumor.
From the worker perspective

Worker does [unexpected action] instead of [expected action]

  • Worker moves the cursor directly to Next instead of reading the instructions.
  • Worker annotates red regions instead of tumor regions.

Reuse an existing problem when it is the same issue. Repeated occurrences are what the Problem summary counts.

5 Severity severity

Critical
  • Slowed down: hindered in solving the task.
  • Understanding: does not understand how information in the system can be used to solve the task; repeats the same information in different parts of the system.
Serious
  • Slowed down: delayed for several seconds.
  • Understanding: does not understand how a specific functionality operates or is activated; cannot explain how the system works.
  • Frustration: clearly annoyed by something that cannot be done or remembered, or something illogical; believes they damaged something.
Cosmetic
  • Slowed down: delayed for a few seconds.
  • Understanding: does actions without being able to explain why ("you just have to do it").

Source: Skov & Stage (2005). Supporting Problem Identification in Usability Evaluations. OZCHI.

6 Problem types type

Navigation
Problems navigating between pages or finding the right links for information or functions. E.g. trouble returning to the home page.
Layout
Difficulties caused by web elements, display or visibility issues, inconsistency, or problematic structure and form design. E.g. the font is too small.
Content
Information is unnecessary or missing, or terminology and dialogue are hard to understand. E.g. does not understand an error message.
Functionality
A function is missing or does not work as expected. E.g. expects an option to choose how many items to load per page.

Source: Alhadreti & Mayhew (2017). J. Usability Studies, 12(3).
